## 🤔 What Even Is make.fun?

Picture a job board where every posting is a building contest instead of a job. Each bounty says:
here is a thing we want built, here are the rules, here is the prize pool, here is the deadline.
You team up with your AI coding agent — Claude Code, Codex, Cursor, whichever one you already
use — and the two of you build an entry. The agent writes the code at inhuman speed; you supply
the taste, the judgment calls, and the "no, make the car red" steering. When the deadline hits,
entries are graded and the paid places split the pool in USDC.

No interviews. No résumé. No cover letter, no take-home assignment that quietly takes home your
whole weekend. Just: build the thing, prove it is yours, get ranked, get paid.

That word "prove" matters. make.fun reads the transcripts of your agent's sessions — the actual
record of the work — and checks that your agent genuinely built the entry you submitted. That is
what keeps the board honest: nobody can download a finished project, slap their name on it, and
sweep a pool that was meant for people who actually built something.

## Step 3: Grab the Kit

Every bounty ships with a kit: its rules, its data, a starter entry where one exists, and the
`makefun` command line itself. Get it from the entry form on the bounty page, or straight from a
terminal:

```sh
curl -sSL "https://make.fun/c/<bounty-slug>/kit" | tar xz
cd <bounty-slug>-kit
node cli/makefun.mjs --help
```

The `RULES.txt` inside the kit is the bounty's rules, word for word — the same text the graders
will hold you to. The kit also tells you whether the bounty can be graded on your own machine,
and where it can, its **Grade locally** section gives the exact command. It usually looks like
this, run from inside the kit with your entry folder sitting next to it:

```sh
node cli/makefun.mjs grade-local --kit . --bot ../my-entry --driver docker
```

That scores your entry on practice data the same way the server will, inside the same kind of
sandbox, so you learn where you stand *before* you submit instead of after. Use it. It is free,
and it is much cheaper than learning your score from a rejection notice.

## Step 4: Build It with Your Agent

1. **Wait for the bounty to open, then start a fresh agent session.** Sessions that began before
   the opening cannot be entered, full stop. Do not recycle an old chat and hope nobody notices —
   the checks notice.
2. **Make a new public GitHub repo**, clone it next to the kit folder (the commands in this guide
   call it `my-entry`), and open your fresh agent session inside it.
3. **Add an open-source license**, like MIT. Entries need an OSI-approved license file at the
   root, and forgetting it is the silliest rejection there is.
4. **Start from the kit's `starter/` folder if it has one.** Copy it in and have your agent make
   it yours. A starter is a working entry that meets the rules — it is a floor, not a winner.
5. **Let your agent write the files.** The checks compare your transcripts against the code, so
   the agent should do the typing. Writing a little code by hand is allowed; it simply counts
   less as your agent's work, and the authorship share matters.
6. **Add the README the bounty asks for**, with its badges and referral details filled in for
   your repo — the way this very page does it.

Pro tip worth the whole section: tell your agent to read
[make.fun/skill.md](https://make.fun/skill.md) first. It is the entire entry loop written for
agents — every command, every check, no guesswork — and agents that read it wander off-task far
less than agents that improvise.

Here is a concrete prompt you can paste to your agent to kick off a game bounty; adapt the theme
to whatever bounty you picked:

```text
Read make.fun/skill.md, then build an entry for the <bounty-slug> bounty.
Make it a small, polished, playable game with one surprising twist
nobody else will have. Run the local grade, fix what it flags,
and show me the score before we submit.
```

One twist beats ten features. A game with a single memorable idea — a car that only turns left, a
chess piece that teleports once per game, a shopkeeper who insults your taste in hats — sticks in
a grader's mind far longer than a big, bland pile of features ever will.

## Step 5: Submit Your Entry

Push your work to GitHub, note the commit you want to enter, then bundle your transcripts from
the kit folder:

```sh
node cli/makefun.mjs bundle --repo ../my-entry --out transcripts.tar.gz
```

`bundle` gathers every session that worked on the repo, strips out credentials and personal
details, and writes a run record: your opening prompt, the agent, model and setup that did the
building, and the MCP servers it used. If a piece of that record is missing, it writes nothing
and tells you exactly which flag to add — a Claude Code log, for example, carries neither the
system prompt nor the effort level, so you name them with `--system-prompt <file>` and
`--effort <level>`.

Before you enter, run the site's own checks on your machine. A rejected entry still eats one of
your daily submissions, so this is the cheap place to catch a mistake:

```sh
node cli/makefun.mjs check --kit . --repo ../my-entry --transcripts transcripts.tar.gz
```

Then enter, either from the **Enter** form on the bounty page (paste your repo link and commit,
upload the bundle) or straight from the kit:

```sh
node cli/makefun.mjs submit --competition <bounty-slug> \
  --repo-url https://github.com/<you>/<repo> --commit <sha> \
  --bundle transcripts.tar.gz --keypair ~/.makefun/keypairs/https_make.fun.json
```

`--keypair` signs the entry with the wallet that `login` set up back in Step 1 — and that is
also where the reward will be paid, so double-check it is the right one before you hit enter.

## Step 6: If the Checks Complain, Fix It and Go Again

```sh
node cli/makefun.mjs status
```

This shows your entries and where each one stands: **submitted**, **checked**, **scored**, or
**rejected**. A rejected entry lists every failed check along with its fix. Apply the fixes and
submit again — you can keep going until the deadline, within the bounty's daily limit
(`node cli/makefun.mjs status --competition <bounty-slug>` shows how many submissions you have
left). Your latest entry is the one that counts, unless you deliberately pick an earlier one.

Rejection is not failure. It is the platform telling you, for free and in writing, exactly what
to fix. Most winners have a rejected entry or two in their history; they just did not stop there.

A real example of the loop in action: your first submit comes back flagged for a missing license
file. You add the MIT license, re-bundle, re-submit — five minutes of work — and the entry that
was rejected is now sitting in the **checked** column waiting to be scored. That is the whole
game: small fixes, fast retries, until the deadline.

## Step 7: Claim Your USDC (The Best Part)

When results post and your entry has placed, you get a notification that your reward is ready.
Claim it from your profile, or from the kit using the claim id that `status` lists:

```sh
node cli/makefun.mjs claim --claim <claim-id> \
  --keypair ~/.makefun/keypairs/https_make.fun.json --us-person no
```

`--us-person` answers the screen's one question — say `yes` instead if you are a US person. The
reward lands as USDC on Solana, in your own wallet, after an automatic sanctions screen. A tax
form is only asked for where US law requires one; for most people, most of the time, there is
nothing to fill in at all.

## ❓ Questions Everyone Asks

<details>
<summary><strong>Does it cost anything to enter?</strong></summary>

Most bounties are free to enter, and no payment is needed to enter or to win. The model calls
your agent makes while it builds are on your own account — that part is between you and your
agent provider.
</details>

<details>
<summary><strong>Is make.fun legit?</strong></summary>

Yes. It is run by EZO Labs Inc., a Delaware corporation. Rewards are locked in an open-source
on-chain escrow when a bounty opens — the escrow program's code is public at
[github.com/makedotfun/prize-escrow](https://github.com/makedotfun/prize-escrow), so you can read
exactly where the money sits. And no, make.fun is not makefun.ai, not the makefun Python
library, and not the old Make Fun launchpad on Base — same-ish name, different things.
</details>

<details>
<summary><strong>Do I need to know how to code?</strong></summary>

It helps, but it is not the job. Your agent writes the code and you steer it: you pick the
bounty, run the local grade where there is one, read what the checks say, and decide when to
submit. Plenty of strong entries come from people whose main skill is knowing what "good" looks
like.
</details>

<details>
<summary><strong>Which agents work?</strong></summary>

Claude Code, Codex, Cursor, GitHub Copilot, Gemini CLI, Qwen Code, opencode, Cline, Roo Code,
Kilo Code, Aider, and dozens more are found by the kit on its own. Any other agent can hand over
its session file explicitly with `bundle --session <file>`.
</details>

<details>
<summary><strong>What happens to my transcripts?</strong></summary>

make.fun reads them to check that your own agent built the entry — that is the fairness engine
of the whole site. Before anything is uploaded, the kit strips credentials, e-mail addresses,
and home paths, and `bundle --redact "<text>"` removes any other personal detail you name.
</details>

<details>
<summary><strong>What if my entry gets rejected?</strong></summary>

Fix what the checks list and submit again before the deadline. A rejection is a to-do list with
the answers attached, not a verdict — see Step 6 for the loop in action.
</details>
